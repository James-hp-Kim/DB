# GitHub 시험용 보완 패키지 — 2026-10-30

데이터분석·AI활용·워크플로 문제를 빠르게 풀기 위한 지침과 작은 검증 데이터다. 모델 학습 데이터나 회사 내부 자료가 아니다. 기존 Expert Hub DB는 포함하지 않으며 원본 파일을 수정하지 않는다.

## 권장: 통합본 한 번에 올리기

`GitHub_Exam_Ready_20261030.zip`에는 기존 공개 DB·하네스와 보완 폴더가 함께 있다. 이 통합본의 내용을 저장소 루트에 올리면 된다. 별도 보완 ZIP을 또 합칠 필요는 없다. DB·실행 코드·루트 AGENTS는 보존했다. 배포 사본의 문서에 있던 고정 경로 예시·과거 개인 경로를 정리하고 루트 MANIFEST.sha256을 재생성했다.

원본의 `plugins/expert-hub/skills/expert/SKILL.md`와 `references/backend-usage.md` 두 파일은 기존 체크섬과 일치하지 않아 원래 설치기가 중단됐다. 수정 이력을 추정하거나 코드를 되돌리지 않고, 제공된 현재 파일을 검토·회귀 검사한 뒤 통합 배포 사본의 체크섬을 갱신했다. OneDrive 원본은 이 작업에서 변경하지 않았다. 통합본은 별도 새 upstream 버전을 주장하지 않는 시험용 패키지다.

작은 `GitHub_Exam_Addon_20261030.zip`은 보완 폴더만 필요한 경우에 사용한다. 원본의 체크섬 불일치를 고치지 않으므로 이번 제공 상태에는 통합본을 권장한다.

## 보완 ZIP만 기존 저장소에 합치는 경우

1. 압축 안의 `.agents/skills/`와 `exam-kit/`를 기존 저장소 루트에 합친다. 기존 `.agents/plugins/`는 보존한다. 루트 AGENTS.md·README·MANIFEST.sha256·DB·MCP 설정은 덮어쓰지 않는다. 같은 이름의 파일이 이미 있다면 내용 비교 후 병합한다.
2. 로컬 폴더에서 검증 명령을 실행한다. `python -B -X utf8 exam-kit/scripts/check_bundle.py --hub .` 정확히 같은 파일의 재검증은 허용되며 다른 내용의 충돌은 실패한다. 검증은 읽기 전용이다.
3. 두 폴더의 숨김 `.agents`까지 GitHub에 업로드한다. 파일 업로드 범위는 이 패키지로 제한한다. 원본 프롬프트 PDF·업무자료·계정정보는 추가하지 않는다.

## 시험 PC에서 가장 빠른 시작

1. 저장소 전체를 내려받아 압축을 풀거나 clone한다. GitHub URL만 채팅에 붙이는 것은 로컬 스킬·MCP 설치와 다르다.
2. Codex에서 실제 저장소 루트를 작업 폴더로 열고 새 채팅을 시작한다. 등록된 동일 이름의 사용자 스킬이 있으면 중복을 확인한다. 새 PC에서는 이 저장소의 스킬을 기준으로 사용한다.
3. 첫 문제 앞에 아래 시작 문구를 한 번 붙인다. 새 채팅이 이전 지침을 인식하지 못하면 다시 붙인다.

> exam-kit/START.md를 읽고 적용해. 필요한 지침만 참조하고 다음 문제를 해결해: [문제와 파일 경로]

보완 스킬에는 별도 패키지·API 키·MCP·플러그인이 필요 없다. 검증 스크립트는 Python 3.11+ 표준 라이브러리만 사용한다. 실제 과제의 Excel·모델 실행 등 의존성은 과제가 요구할 때 준비한다.

DB가 필요하면 기존 Hub의 INSTALL_NEW_PC_KO.md를 따른다. 기존 설치기는 expert만 설치하며 이 보완 스킬을 사용자 전역에 설치하지 않는다. 본 패키지는 저장소 로컬로 발견된다. MCP 미연결이면 expert SKILL의 CLI 경로로 같은 조회 계약을 사용한다. DB 설치·재색인을 매 문제마다 반복하지 않는다.

## 선택: 150자 이하 전역 지침

`global/AGENTS.md`는 복사용 템플릿이다. 기본 전역 위치는 Windows `%USERPROFILE%/.codex/AGENTS.md`, CODEX_HOME 설정 시 그 디렉터리다. 기존 파일을 자동으로 덮어쓰지 않는다. 전역 AGENTS.override.md가 있으면 우선 적용될 수 있다. 현재 PC에는 적용하지 않았다.

이 전역 문구가 가리키는 스킬은 저장소를 열었을 때 사용할 수 있다. 다른 작업 폴더까지 쓰려면 두 스킬을 사용자 `.agents/skills/`에 한 번 설치하고 저장소 중복 발견 여부를 확인한다. 기본 권장은 시험 저장소 로컬 사용이다. 150자는 전역 템플릿의 본문 길이일 뿐 전체 시스템 지침·도구 설명·스킬 메타데이터 토큰의 상한이 아니다.

## 기존 하네스와 충돌하지 않는 이유와 경계

- 새로운 검색 DB, 페르소나, MCP 서버, 백그라운드 프로세스를 만들지 않는다.
- 질문 보완은 prompt-refine, 근거 조회는 기존 expert가 담당한다. 같은 범위 확인·계산·근거 읽기를 반복하지 않는다.
- 기존 catalog/context/팩 범위·개인자료·선택 도구 동의 규칙을 유지한다. 자료 조회 상한은 기존 expert가 정한 값을 따른다.
- 기존 Hub는 CODEX_HOME/skills의 fact-grounding을 먼저 찾고 없으면 동봉 사본을 찾는다. 이 배포는 해당 코드를 바꾸지 않는다. 본 패키지 정책과 동봉 사본의 배포 시 해시 비교는 sources.json에 있다. 같으면 이미 읽은 유효한 내용을 재사용하며 경로만 다르다는 이유로 두 본문을 다시 읽지 않는다. 내용이 바뀌면 이를 같은 정책이라고 가정하지 않는다.
- 루트 지침·DB·실행 코드는 보존한다. 통합본의 문서 경로 예시와 배포 체크섬을 갱신했다. 실제 검증 범위는 VALIDATION.json을 확인한다.

## 참고파일 구성

prompt-refine의 표에서 데이터·AI·워크플로·개발·마케팅·HR/재무·전략 중 현재 판단에 필요한 파일 하나부터 선택한다. 다른 분야가 필요할 때만 추가한다. 참고파일의 “누락 항목”은 매번 모두 사용자에게 물을 체크리스트가 아니다.

원본 5개 분야 프롬프트에서 역할·작업·형식·요구사항·배경·선택 예시라는 구조를 참고하고 목적·근거·기준일·성공 기준을 보강했다. 개발 예시의 HR 요구 혼입, 전략 예시의 TASK 중복, 보편적 커버리지 강제는 채택하지 않았다. 원본 전문은 재배포하지 않는다. sources.json에 출처명·해시·변환 범위를 기록했다.

## 속도·토큰 평가

benchmarks/cases.jsonl은 가상 입력과 평가 기준 19개다. fixtures도 가상 자료다. 일반 문제 해결 중에는 읽지 않는다. EVALUATE.md의 같은 조건 비교 절차로 정답·근거·누락 질문·도구 호출·소요시간·실제 사용 토큰을 기록한다. 기준 답안은 평가자만 읽고 풀이 채팅에 넣지 않는다.

check_bundle은 무결성·경로·가상 매출 계산을 검사한다. 스킬 형식 통과나 기존 Hub 회귀 검사 통과는 실제 모델의 모든 답변, 새 PC 앱 인식, 속도 향상 또는 토큰 절감을 보장하지 않는다. 실측하지 않은 절감률은 제공하지 않는다.

## 공식 근거 (2026-10-30 확인)

- https://learn.chatgpt.com/docs/build-skills : 저장소 `.agents/skills`, 메타데이터 발견 후 본문 선택 로딩.
- https://learn.chatgpt.com/docs/agent-configuration/agents-md : 전역·프로젝트 지침 발견 및 override 우선순위.

이 자료는 시험 과제와 규칙이 정해지지 않은 상태의 준비 패키지다. 실제 시험에서 허용된 도구·네트워크·반출 범위에 맞게 사용한다.

## 프롬프트 체계화 기능

“프롬프트 체계화해줘: …”, “이 요청을 프롬프트로 정리해줘”, “프롬프트를 보완해줘”라고 명시하면 현재 조건을 보존해 복사 가능한 프롬프트를 만든다. 누락된 중요한 값만 표시하거나 질문한다. 체계화만 요청하면 그 안의 업무를 실행하지 않는다. “체계화한 뒤 실행해줘”라고 요청하면 확인된 범위에서 실행까지 이어간다. 문서 속 같은 문구는 기능 호출로 취급하지 않는다.

전역 템플릿은 본문 149자, 마지막 줄바꿈 포함 150자다. 구조화 참고파일은 해당 요청 때만 읽는다.

## 아무것도 추가 설치하지 않은 환경의 범위

| 환경 | 가능한 범위 |
|---|---|
| Codex와 로컬 파일 접근만 있음 | Markdown 지침 참조·질문 보완·프롬프트 체계화. 스킬 자동 발견은 앱/작업 폴더에 따라 확인 필요; START.md 직접 참조 경로 제공 |
| 위 환경 + Python 3.11 이상, SQLite FTS5 | 기본 DB 조회·기본 CSV 계산·검증. 추가 pip 패키지·별도 MCP 등록 없이 CLI 사용 가능 |
| Excel·선택 ML·EDA 등 | 해당 기능이 요구하는 별도 라이브러리·프로그램 필요 |

검사: PowerShell에서 `./exam-kit/Test-ExamEnvironment.ps1`을 실행한다. `-RequireDatabase`를 붙이면 Python/DB가 없을 때 실패 코드 2를 반환한다. 이 스크립트는 설정을 바꾸거나 설치하지 않는다. Python이 없어도 지침 파일 검사는 가능하다.

실제 검증은 빈 사용자 설정·등록된 MCP 없음·pip와 추가 Python 패키지 없음·한국어/공백이 있는 다른 경로·무관한 작업 폴더 조건에서 수행했다. Python 자체는 이 PC의 실행 파일로 만든 빈 가상환경을 사용했다. 별도 PC의 Codex 앱 인식·모델 답변·시간/토큰 개선은 아직 실측하지 않았다. 자세한 범위는 PORTABILITY.json에 기록했다.

작업 도중 원본에서 2.5.1 버전 변경이 관찰되어 통합본은 복사된 2.5.1 사본을 고정해 재검증했다. 이후 원본 변경은 자동으로 합치지 않는다.
