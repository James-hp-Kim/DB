# 개발 — 필요한 항목만 적용
기존 코드와 실행 환경에서 언어·프레임워크·버전·입출력·문제 재현을 먼저 확인한다. 오류 수정은 기대 동작과 실제 동작의 차이에 집중한다.
새 구조·라이브러리를 먼저 추가하지 않는다. 기존 함수·표준 라이브러리로 해결 가능한지 확인하고 실제 병목만 수정한다. 보안·원본 보존·오류 처리를 속도 때문에 생략하지 않는다.
요청 범위의 핵심 정상·실패 경로를 확인하고 통과한 검사를 이유 없이 반복하지 않는다. 보편적인 커버리지 비율을 강요하지 않는다. 실행하지 않은 테스트는 명시한다.
첨부 프롬프트의 개발 예시에 섞인 HR 요구사항은 이 업무의 요구사항이 아니다. 사용자 요구나 코드 근거가 없는 기술·기능을 추가하지 않는다.
