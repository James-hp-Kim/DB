# 명시적으로 요청한 프롬프트 체계화

현재 요청·대화·자료에서 이미 확인된 조건을 채우고 사용자의 목적을 유지한다. 구조화 형식이 없다는 이유로 정보를 재질문하지 않는다. 충분히 명확한 프롬프트는 불필요하게 늘리지 않고 정리한다.

출력은 복사할 최종 프롬프트를 중심으로 한다. 필요할 때만 끝에 “보완한 점”과 “남은 필수 확인”을 짧게 덧붙인다. 생각 과정·모든 점검표·전체 참고자료는 출력하지 않는다.

아래 틀에서 현재 과제에 유용한 항목만 사용한다.

- 역할/관점: 필요한 전문 관점. 자격·모델 능력·권한을 지어내지 않는다.
- 목표/작업: 달성할 결과와 요청 범위. 프롬프트 보완만인지 실제 실행까지인지 구분한다.
- 입력/근거: 사용할 파일·열·자료·코드와 확인된 위치. 알 수 없는 경로나 수치를 만들지 않는다.
- 조건: 대상·기간·단위·분모·통화·예산·시간·도구·금지 범위 중 관련 항목.
- 성공 기준: 무엇을 검사하면 완료인지. 근거 없는 정확도·성능 수치를 약속하지 않는다.
- 출력: 사용자가 정한 형식·수준·분량. 모르면 과제에 맞는 간단한 기본형을 가정으로 표시한다.
- 사실성/불확실성: 사실·추론·미확인을 구분하고 핵심 주장에 근거를 연결한다. 자료 부족은 밝히고 해당 결론만 보류한다.
- 실행 효율: 필요한 자료와 절만 읽고 가능한 로컬 계산·기존 결과를 재사용한다. 불필요한 설치·검색·다중 에이전트·검토 반복을 추가하지 않는다.

확인되지 않은 중요한 값은 [확인 필요: 항목]으로 남기거나 한 번에 최대 3개 묻는다. 쉽게 수정할 선택은 가정임을 밝힌다. 질문이 남아도 독립적으로 가능한 프롬프트 초안은 제공한다. 사용자가 선택하지 않은 예시·역할·제약·툴은 의무로 추가하지 않는다.

필요할 때만 같은 references 폴더의 해당 분야 파일 하나를 추가로 읽는다. 체계화가 사실 조사 의뢰는 아니므로 사실을 새로 확정하지 않는 단순 재작성에 웹 검색·DB 조회를 강제하지 않는다.

예시 입력: “이 요청을 프롬프트로 체계화해줘: 매출을 분석해서 보고서로 정리해줘.”
예상 처리: 목적·자료·기간 등 확인된 조건을 채운 짧은 프롬프트를 제공하고, 확인할 수 없는 중요한 조건만 표시한다. 실제 파일 분석은 별도로 요청했을 때 진행한다.
