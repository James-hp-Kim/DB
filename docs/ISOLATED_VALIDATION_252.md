# 2.5.2 격리 설치와 실제 호출 검증

## 결과

수정한 테스트 2개가 통과했고 전체 회귀도 117개 모두 통과했다. 같은 Windows PC 안에서 Python 3.14.7 가상환경을 새로 만들고, 한글·공백 경로의 빈 설치 위치와 별도 CODEX_HOME으로 실행했다. 기본 Python 환경에는 pip만 있었고 DB/MCP·기본 분석을 위해 외부 패키지를 설치하지 않았다. 유지보수 전체 회귀는 기존 별도 검증용 가상환경으로 실행했다.

| 단계 | 확인 결과 |
|---|---|
| 배포 해시 | 원래 2.5.1 압축본 해시 목록 일치 |
| 수정 테스트 | backend inventory / RTL common record preservation 2개 통과 |
| 전체 회귀 | 117개, 실패·skip 없음 |
| 새 설치 | Setup-NewPC.ps1에 새 Python 및 격리 SkillDestination 전달; 실제 파일 복사·MCP 등록·설치 후 검사 성공 |
| 9개 역할 | 새 stdio 연결에서 catalog/lookup/read/source 및 동봉 사실성 지침 사용 확인 |
| Codex 스킬 발견 | 실제 codex-cli 0.164.0 app-server의 skills/list에서 expert/exam-setup enabled 확인 |
| Codex MCP | app-server가 expert-knowledge 서버의 5개 도구 발견; 실제 catalog→lookup→read→source 호출 성공 |
| Plugin 경로 | 별도의 빈 plugin 설정에서 로컬 marketplace 등록·Plugin 설치, 두 스킬 발견과 MCP 실제 호출 성공 |
| 새 합성 분석 | 설치된 비교 프로그램과 CSV profile 실행; 수치 및 거부 조건 확인 |
| Excel/PDF | 별도 새 가상환경에서 XLSX 읽기·계산·쓰기·재읽기, 텍스트 PDF 생성·추출 성공 |

스킬은 실제 app-server 검색 결과의 경로와 enabled 상태로 확인했다. 단순 파일 존재만 확인한 것이 아니다. MCP도 등록 목록만이 아니라 Codex 연결을 통한 실제 호출까지 확인했다. 별도 계정 인증/모델 추론 없이 수행했으며 현재 Codex 대화에서 받은 결과와 로컬 계산으로 분석했다. Desktop UI에서 새 대화를 열어 모델이 자동으로 수행하는 시나리오는 확인하지 않았다.

## 발견하여 보완한 내용

별도 CODEX_HOME과 자식 프로세스 HOME/USERPROFILE만으로는 Windows 사용자의 기존 `.agents/skills`가 검색 목록에서 사라지지 않았다. 기존 사용자 스킬을 수정하거나 삭제하지 않고 **격리 CODEX_HOME의 설정에만** 해당 경로를 disabled로 지정했다. 재확인에서 격리 폴더 밖 활성 스킬은 0개였다. 시스템 기본 스킬은 격리 CODEX_HOME 안에 준비됐다. 이는 앱 설정과 파일 위치의 격리이며 새 Windows 계정/VM/OS 접근 통제를 의미하지 않는다.

Plugin 스킬은 `expert-hub:expert`, `expert-hub:exam-setup`으로 표시됐다. 설치 메시지와 문서의 `$expert` 안내를 설치 방식별로 구분했다. Plugin의 MCP 서버 이름은 `expert-knowledge`였다. 기본 Skill 설치는 expert만 복사하며 exam-setup 추가 복사 경로도 실제로 수행했다.

시험 코드 자체의 인수 위치 오류와 CSV 열 인수 구분 오류가 한 번씩 발생했다. 제품은 잘못된 입력을 거부했으며 시험 코드를 수정해 재실행했다. 원래 오류 출력은 별도 검증 묶음에 보존했다. 2.5.1 원래 실패 기록도 바꾸지 않았다.

## 실제 분석의 범위

새로 만든 **가상 요약자료**에서 60초·12,000요청·동일 자원/부하라는 조건 아래 p95 450→180ms(−60%), 오류율 5→0.5%, 성공 처리량 190→199건/초를 계산했다. 실제 부하 측정 결과가 아니므로 성능 개선 실적이나 운영 SLO 달성으로 표현하지 않는다.

부하가 200→100요청/초로 바뀐 입력은 not_comparable로 거부하고 상대 개선 수치를 반환하지 않았다. 응답 정확성 실패 1건이 있는 후보도 실패로 반환했다. 별도 연결 풀 모형은 80회 요청에서 예외 반환 누락으로 acquire timeout 60회 발생; 재시작만 하면 다시 60회; finally 반환에서는 0회이고 가용 연결 4개가 복원됐다. 주입한 애플리케이션 오류 16회는 숨기지 않았다. 실제 DB 드라이버·취소·트랜잭션·HTTP 장애 대응 검증은 아니다.

원인 분석은 모형 내 예외 반환 누락에 한정한다. 임시조치는 유입/비필수 작업 제한과 대상·진행 중 요청을 확인한 제한적 재시작, 영구수정은 성공/예외/취소 경로 반환 및 트랜잭션 종료/불량 연결 폐기다. 재시도·중복 업무 영향은 읽기 전용 원장 대조가 별도로 필요하다. 운영 조치나 실제 업무 데이터 변경은 수행하지 않았다.

Excel 검사는 3행, 검사 600개·불합격 12개로 2%를 계산해 다시 읽었다. PDF는 이 숫자가 담긴 영문 텍스트의 생성·추출을 확인했다. 수식 재계산, OCR, 한글 PDF 글꼴, 시각 렌더링, Codex 전용 스프레드시트 실행 기반은 미검증이다. `requirements-file-roundtrip-validated.txt`는 이 좁은 기능의 실제 설치 버전 기록이며 전체 시험용 패키지 lock이 아니다.

## 보존과 남은 한계

기존 전역 config/AGENTS 및 사용자 `.agents/skills` 파일 해시를 실행 전후 비교한다. 로그에는 비밀키나 인증파일을 복사하지 않았다. 코드·정본·자료를 삭제하지 않았고 GitHub 업로드도 하지 않았다.

Python과 Codex 실행 파일은 원래 PC에 설치된 것을 사용했다. 새 OS 설치, Python 자체 다운로드/설치, Codex 신규 로그인, 조직 정책·프록시, 다른 Python 버전, 전체 선택 ML 패키지 설치는 검증하지 않았다. 따라서 표현은 **같은 Windows의 격리 설정·가상환경에서 설치와 실제 호출·합성 분석 성공**으로 제한한다.

공식 API 구조 참고: [Codex app-server 문서](https://learn.chatgpt.com/docs/app-server). 실제 요청은 로컬 설치 버전이 생성한 JSON 스키마와 응답으로 대조했다. 현재 공식 문서와 설치 버전의 모든 기능이 동일하다고 가정하지 않았다.

최종 2.5.2 재설치 결과와 기존 설정 보존 결과는 RELEASE_STATUS_252.json 및 별도 newpc-validation-20261030.zip에서 확인한다. 과거 2.5.1 보고서는 당시 상태로 유지한다.

## 최종 배포 후보 재설치

2.5.2 압축 후보를 새 위치에 풀고 빈 MCP 설정에서 설치했다. 9개 역할 서버 검사, Skill과 Plugin 각각의 Codex 실제 발견/네 번의 MCP 조회, 설치된 2.5.2 분석 실행을 다시 확인했다. 이후 최종 ZIP에는 검증 보고서·상태만 추가했고, 실행 관련 868개 파일은 실제 설치·검사한 후보와 해시가 같다. 전역 설정/AGENTS/사용자 스킬 859개 경로의 내용·존재 상태와 정본/DB 28개 파일이 보존됐다. 사용자 데이터·계정 인증은 가져오지 않았다.
