## 최소 자료 조회 측정

data-analyst 허용 범위(common/analytics/sales/quality)의 67개 카드를 한꺼번에 읽는 비교 기준은 23,409 참조 토큰입니다. 같은 진입 Skill·CSV 프로파일을 포함한 네 가지 선택 조회는 1,900~2,109입니다. 약 91.0~91.9% 작은 텍스트 입력입니다.

측정은 o200k_base, 고정 질문·선택 ID, 조건/절차/한계와 출처를 대상으로 합니다. 실제 Codex 과금·추론·답변·도구 정의·누적 대화는 제외했습니다. 검색 품질의 일반적 보장이나 최소 토큰 최적해가 아닙니다. [세부 결과](data-analysis-benchmark.json).

## 통합 변경과 범위

- HBM F060–F062의 검열·Weibull·Arrhenius 정의를 quality:reliability에 보강했습니다. 기존 본문·출처를 유지하고, [변경 전 레코드·해시·변경 필드](INTEGRATION_AMENDMENTS.json)를 남겼습니다. 원래 RTL 보존 해시는 수정하지 않았고 회귀에서 이 명시적 추가만 허용합니다.
- HBM 출처의 확보상태·검토범위 메타데이터를 필요한 source 조회에 반환합니다. acquisition은 해당 URL 시도 상태이며 모든 원문 확보 여부와 항상 같지는 않습니다.
- RTL 검증 로그의 RESULT PASS/FAIL/MISMATCH를 관련 검증 지식으로 연결합니다. 문구를 발견하는 기능이며 결함 확정이나 실제 EDA 재검증이 아닙니다.
- 각 분야의 과거 검증 문서는 당시 고정 사본의 기록입니다. 최신 통합 수량·통과 여부는 이 문서를 우선합니다. HBM/RTL/데이터 참조 토큰 JSON은 이번 합본에서 다시 측정했습니다.

사용자 실제 매출·실리콘·현업 장애 자료의 성능은 검증하지 않았습니다. 회사 채택·내부 기준·모델 가중치 학습 완료를 뜻하지 않습니다. 딥러닝/GPU·분산 엔진·계층 조정·예측구간·외생변수 연결은 별도 구현이 필요합니다. 실제 Codex 앱 대화에서 자동 스킬 선택을 확인한 것이 아니라 격리된 CLI 설치·SDK 연결을 검사했습니다. 전체 원문 305건을 이번 통합에서 다시 읽었다는 주장도 하지 않습니다.

## 배포 무결성 확인

MANIFEST.sha256는 배포 파일 전체의 SHA-256을 포함합니다(자기 자신 제외). 압축을 푼 뒤 `python -B -X utf8 scripts/verify_release.py`로 확인하세요. `.gitattributes`는 Git의 줄바꿈 자동 변환에 의한 체크섬 변경을 방지합니다. ZIP 외부 체크섬과 압축해제 검증 결과는 ZIP 옆의 RELEASE_CHECK.json에 제공합니다.
