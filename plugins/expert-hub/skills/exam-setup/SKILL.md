# Windows Codex 시험환경 준비

현재 요청이 실행을 허용하는지 먼저 구분한다. 설치 자료 점검·구성 준비는 설치 권한이 아니다. 사용자가 동작 검증을 금지하면 Python probe, 설치기, MCP 호출, 샘플 실행, 테스트를 실행하지 않고 파일 읽기와 구성 보완만 한다. 미실행 상태를 남긴다.

기본은 단일 Codex와 로컬 Python 도구다. 외부 AI 에이전트 연결, 별도 모델 API, 선택 플러그인을 기본 설치에 넣지 않는다. 기존 설정·동명 Skill/MCP를 덮어쓰지 않는다. 승인된 작업은 불필요하게 다시 묻지 않는다.

1. 이 스킬의 실제 위치를 기준으로 경로를 계산한다. 설치된 `fact-grounding`을 읽고, 없으면 형제 `../expert/references/fact-grounding.md`를 읽어 대체 사용을 밝힌다. 둘 다 없으면 파일 누락을 보고하고 사실/추론/미확인 구분을 유지한다.
2. 사용자 자료에서 Windows/Codex 사용 가능 여부, 설치·네트워크 권한, 입력/제출 형식과 시간 예산을 확인한다. 이미 알려진 조건은 재질문하지 않는다. Codex 로그인과 Python 3.11+ 및 SQLite FTS5는 별도 전제다. 아무 런타임도 없는 PC에서 Skill만으로 분석·MCP가 작동한다고 말하지 않는다.
3. 원본 배포 폴더가 있으면 `INSTALL_NEW_PC_KO.md`와 `docs/EXAM_SETUP_KO.md`를 읽는다. 없으면 임의 경로를 만들지 말고 실제 압축 해제 위치를 확인한다. 설치 승인 시 기존 설치기를 사용한다. `Setup-NewPC.cmd`는 설치뿐 아니라 실행 검사도 수행하므로 검증 금지 상태에서는 사용하지 않는다. `-ManualMcp`도 검사 생략 옵션이 아니다.
4. 필요한 지침은 형제 `../expert/SKILL.md`로 연결한다. DB가 유용한 문제만 catalog → 제한 lookup → 선택 절 → source로 조회한다. 데이터·반복 계산은 로컬에서 처리하고 전체 행을 대화에 올리지 않는다. DB 무결과는 분석 중단 사유가 아니다.
5. Excel/PDF가 필요하면 현재 Codex 도구의 실행 기반 제공 여부를 구분한다. 제공 스킬을 복사해서 전용 실행 기반이 설치됐다고 말하지 않는다. 대체 경로는 openpyxl(Excel), pypdf(텍스트 PDF)이며 스캔 PDF OCR, 수식 재계산, 화면·레이아웃 검증은 별도다. 필요한 라이브러리만 작업용 가상환경에 설치한다. 검증되지 않은 버전 조합을 확정하지 않는다.
6. 실행 허용 시에만 해당 기능의 작은 입력→출력 확인과 실제 Codex 연결 확인을 한다. 파일 존재/설치/발견/호출/출력 정확성을 구분해 보고한다. 관련 확인이 끝나면 반복 검사하지 않는다. 이후 문제 해결에는 [작업 템플릿](references/task-template.md)을 필요할 때만 참고한다.

Ponytail, Context7 등 선택 방법은 expert의 기본 비활성·범위별 동의 정책을 따른다. 이 스킬은 자동 설치 프로그램이나 전역 프롬프트가 아니다. 설치되지 않았거나 이번 작업에서 읽지 않은 스킬을 적용했다고 주장하지 않는다.
